## Finding that governs the plan

The current app captures a complete WAV, transcribes after release, optionally calls a resolver, then stages and pastes exactly once. It does not produce live ASR hypotheses. Its production contextual resolver rejects personal dictation before matching or dispatch, even when the local beta switch is on. The only real provider route is a separately authorized, durable, one-shot synthetic diagnostic. Enabling automatic personal JEV calls would change privacy and cost policy, not merely improve an existing stream.

`DecisionsStreamingTransport` means bounded HTTP body delivery. `OpenRouterDecisionsClient.perform` collects the complete JSON response and only then decodes a typed receipt; there is no provider token stream, audio stream, or incremental semantic result interface. Millisecond-scale local presentation can be a target; remote inference or complete audio-to-text latency has no measured millisecond guarantee here.

## Smallest plausible integration, for architecture synthesis

Use a single session owner for immutable partial hypotheses, revisions, bounded PCM/context, scheduling, and preview. Extend the existing recorder/transcriber seams instead of adding another speech provider or model dependency. Keep local capture and decoding off the UI actor, retain the existing serialized engine, and enforce latest-only/backpressure before dispatch so chunk production cannot create unbounded work. Exact window/overlap/stability thresholds require real hardware evidence; no value is justified by source analysis alone.

Each event/decision needs session UUID, monotonically increasing revision, source sample range, snapshot identity, language, policy/store generation and whether the relevant span remains mutable. These are proposed contracts, not current symbols. Retain only a bounded mutable suffix and explicitly committed prefix. A result may affect only the exact revision/window for which it was requested; stale, duplicate, reordered, expired and post-finalization events are discarded. Swift `String.Index` values cannot be reused against another hypothesis string, even when the printed prefix looks identical. Bind ranges to the immutable source snapshot and revalidate exact content before applying.

Render hypotheses inside Resenha's HUD while recording. Freeze one final string before `DictationOutputSink.stage`; let the existing one-shot insert/history/feedback path receive it once. Do not read/write other apps incrementally, issue backspaces, overwrite clipboard on each hypothesis, rewrite existing history, or create global glossary rules from contextual decisions. An iPhone-like *preview* is compatible with current insertion architecture; continuous cursor insertion is a materially different feature requiring an editor/undo/ownership contract absent here.

Keep local-only mode fully functional and default remote access closed. A personal remote mode needs its own explicit consent and approved cost limits before activation: exact allowed text, request count/rate/concurrency, total/session budget and stop conditions. There is no such budget ledger or personal-consent owner at HEAD. Cached decisions, if introduced, must be bounded and invalidated by session, source/window identity, language, policy, store mutation and model; no cross-session personal transcript cache by default. Persistent semantic learning remains explicit confirmed examples only.

## High-risk findings and required checks

|---|---|---|
| Critical: paid personal transmission | Production scope is blocked today; diagnostic credential/guard is single-use synthetic only. | Separate authorization and cost boundary; offline/disabled tests assert zero transport opens even with credential present; no provider calls in this planning task. | High: unbounded queue/latency | Whole WAV + full decode + single semaphore; a task per frame would accumulate. | Bounded buffers and latest-only scheduling, one inference owner, explicit finalization budget; measure capture→hypothesis, hypothesis→UI, context dispatch→decision and release→paste separately with p50/p95/p99, cold/warm model and hardware identification. |

## Open design inputs, not blockers to source analysis

Architecture must choose a bounded PCM window/overlap and stability definition after a local benchmark; source offers no calibrated values. Product must distinguish live HUD preview from incremental writing into external apps. The user goal requests continuous contextual intelligence but does not itself supply a paid API budget, recurring personal-data consent or permission to repurpose diagnostic credentials. The plan can finish local/core work and define a closed remote extension while keeping paid validation explicitly gated.
